# AV Control 1.6.1

## Polski

Agent 1.1.1 naprawia fałszywy alarm systemu plików tylko do odczytu. Odróżnia stan nośnika od ograniczeń widoku usługi, zachowując `ProtectSystem=strict`. Brak miarodajnego pomiaru daje wynik nieznany. Poprawka obejmuje aktualizację Runtime i nowy obraz; nie wymaga zmiany projektu.

Powiadomienia e-mail w TECHNIKAV mają czteroetapowy kreator Proton Mail: nadawca i token SMTP, bezpieczne sprawdzenie połączenia, odbiorcy i zdarzenia, zapis i harmonogram. Token jest szyfrowany poza katalogiem publicznym i nie trafia na Raspberry Pi. Test połączenia nie wysyła wiadomości; osobny przycisk pozwala wysłać jeden test po zapisaniu ustawień. Wysyłka jest domyślnie wyłączona.

Wymagany jest hosting z nowym kreatorem oraz płatny plan Proton Mail z adresem własnej domeny i dedykowanym tokenem SMTP. Serwer `smtp.protonmail.ch:587` wymaga STARTTLS i prawidłowego certyfikatu. Hasło do skrzynki nie zastępuje tokenu. [Oficjalna instrukcja Proton](https://proton.me/support/smtp-submission).

Kreator zachowuje zakresy uprawnień odbiorców i pozwala wybrać poziom alarmów oraz informację o powrocie do poprawnego stanu. Kolejka grupuje zdarzenia i ogranicza częstotliwość. Niepewna wysyłka wymaga jawnego ponowienia; harmonogram aktualizacji TECHNIKAV może obsługiwać włączoną pocztę. Przyjęcie przez SMTP nie jest dowodem doręczenia.

Główny podręcznik zaktualizowano w miejscu: **195 stron, 52 rozdziały, 4 dodatki, 75 ilustracji**. Rozdział 49 opisuje wszystkie kroki kreatora, tokeny, harmonogram, błędy i wymianę tokenu. Ćwiczenia są scalone z oryginalnym programem **10 sesji / 22 godziny**.

To poprawka diagnostyki i dokumentacji. Podgląd logiki, stan UDP/TCP/portów, tła paneli, konta, klawiatura i metryka projektu zachowują funkcje 1.6.0. Raport wydania rozdziela nowe próby od bazowych testów i benchmarku 1.6.0. Testy SMTP używają lokalnego serwera z TLS; rzeczywiste konto Proton i odbiór w skrzynce wymagają konfiguracji właściciela. Fizyczne HDMI, dotyk, nowy rozruch SD, RPi 3B/5 oraz elektryczna komunikacja z zakupionymi konwerterami pozostają osobnymi próbami sprzętowymi.

## English

Agent 1.1.1 fixes the false read-only filesystem alarm. It distinguishes backing storage from the service's restricted mount view while keeping `ProtectSystem=strict`. An unavailable measurement remains unknown. The fix is included in the Runtime update and fresh image and needs no project changes.

TECHNIKAV email notifications now have a four-step Proton Mail wizard: sender and SMTP token, secure connection check, recipients and events, then save and scheduling. The token is encrypted outside the public web directory and never sent to the Raspberry Pi. The connection check sends no message; a separate button can send one test after saving settings. Sending is disabled by default.

This requires the updated hosting wizard and a paid Proton Mail plan with a custom-domain address and a dedicated SMTP token. `smtp.protonmail.ch:587` requires STARTTLS and a valid certificate. The mailbox password cannot replace the token. [Official Proton instructions](https://proton.me/support/smtp-submission).

The wizard preserves installation access rules and lets the owner choose alarm severity and recovery notifications. The queue groups events and limits frequency. Uncertain sends require explicit retry; the existing TECHNIKAV update schedule can process enabled notifications. SMTP acceptance does not prove delivery.

The original handbook is updated in place: **195 pages, 52 chapters, 4 appendices and 75 illustrations**. Chapter 49 covers the wizard, tokens, scheduling, failures and token rotation. Exercises are integrated into the original **10-session / 22-hour** programme.

This is a diagnostics and documentation hotfix. Logic preview, UDP/TCP/serial status, panel backgrounds, accounts, keyboard and project records retain the 1.6.0 features. The release report distinguishes new checks from the explicitly labelled 1.6.0 functional and benchmark baseline. SMTP tests use a local TLS server; a real Proton account and inbox receipt require owner configuration. Physical HDMI, touch input, fresh SD boot, Pi 3B/5 and electrical communication with the purchased adapters remain separate hardware acceptance tests.
