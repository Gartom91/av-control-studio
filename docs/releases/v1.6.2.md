# AV Control 1.6.2

## Polski

Naprawiono błąd klawiatury wirtualnej widoczny w Playerze Linux: podczas szybkiego przejścia z loginu do hasła ostatni klawisz mógł przywrócić fokus do poprzedniego pola. Nowy test sprawdza 40 szybkich zmian pola i zachowanie znaków; test natywnego GTK/WebKit odtwarza ten sam przypadek. Wydanie zastępuje testowe 1.6.1, którego plików nie zmieniano.

Agent 1.1.1 odróżnia stan nośnika od ograniczeń widoku usługi i usuwa fałszywy alarm systemu plików tylko do odczytu, zachowując `ProtectSystem=strict`. Poprawka obejmuje Runtime i nowy obraz; nie wymaga zmiany projektu.

Na hostingu **TECHNIKAV 0.12.408** dostępny jest czteroetapowy kreator Proton Mail w karcie kontrolera → Diagnostyka → Powiadomienia e-mail. Prowadzi przez adres i dedykowany token SMTP, kontrolę STARTTLS bez wysyłania wiadomości, odbiorców i zdarzenia oraz zapis i harmonogram. Token jest szyfrowany poza katalogiem publicznym i nie trafia na RPi. Wysyłka jest domyślnie wyłączona; osobny przycisk wysyła pojedynczą wiadomość testową po zapisie konfiguracji.

Wymagany jest płatny plan Proton obsługujący własną domenę, aktywny adres i dedykowany token SMTP. Hasło do skrzynki nie zastępuje tokenu. Połączenie z `smtp.protonmail.ch:587` wymaga STARTTLS i poprawnego certyfikatu. [Instrukcja Proton](https://proton.me/support/smtp-submission).

Odbiorcy zachowują zakres dostępu do instalacji. Kolejka grupuje zdarzenia, ogranicza częstotliwość i wymaga jawnego ponowienia niepewnej wysyłki. Harmonogram aktualizacji TECHNIKAV może obsługiwać powiadomienia. Przyjęcie przez SMTP nie potwierdza dostarczenia do skrzynki.

Główny podręcznik zaktualizowano w miejscu: **195 stron, 52 rozdziały, 4 dodatki i 75 ilustracji**. Rozdział 49 opisuje kreator, tokeny, harmonogram i błędy. Ćwiczenia są scalone z oryginalnym programem **10 sesji / 22 godziny**. Dokumentacja i neutralne przykłady są dostępne w pakietach wydania.

Raport i manifest rozdzielają próby nowych pakietów od bazowych testów funkcji i benchmarku 1.6.0. Testy SMTP korzystają z lokalnego serwera TLS; rzeczywisty token Proton i dostarczenie e-maila wymagają konfiguracji właściciela. Fizyczne HDMI, dotyk USB, rozruch nowej SD, RPi 3B/5 i elektryczna komunikacja z zakupionymi konwerterami pozostają osobnymi próbami sprzętowymi. Pakiety nie mają podpisu Authenticode wydawcy.

## English

Fixed the virtual keyboard focus race observed in the Linux Player: a pending edit from the last key could return focus to the previous input during a quick username-to-password switch. A new regression checks 40 rapid field switches and preserves entered text; the native GTK/WebKit test reproduces the same case. This release replaces prerelease 1.6.1 without modifying its assets.

Agent 1.1.1 distinguishes backing storage from the service's restricted mount view, fixing the false read-only filesystem alarm while retaining `ProtectSystem=strict`. The Runtime update and fresh image include the fix; projects need no changes.

**TECHNIKAV hosting 0.12.408** adds a four-step Proton Mail wizard under controller → Diagnostics → Email notifications. It covers the sender and dedicated SMTP token, a STARTTLS check without sending mail, recipients and events, then save and scheduling. The token is encrypted outside the public directory and never sent to the Pi. Sending is disabled by default; a separate button sends one explicit test after configuration is saved.

A paid Proton plan supporting a custom domain, an active address and a dedicated SMTP token are required. The mailbox password is not an SMTP token. `smtp.protonmail.ch:587` requires STARTTLS and certificate validation. [Proton instructions](https://proton.me/support/smtp-submission).

Recipient installation access remains enforced. The queue groups events, limits frequency and requires explicit retry for uncertain sends. The existing TECHNIKAV update schedule can process notifications. SMTP acceptance does not prove inbox delivery.

The original handbook is updated in place: **195 pages, 52 chapters, 4 appendices and 75 illustrations**. Chapter 49 covers the wizard, tokens, scheduling and troubleshooting. Exercises remain integrated into the original **10-session / 22-hour** programme. Documentation and neutral examples are included in release packages.

The report and manifest separate new package checks from the explicitly labelled 1.6.0 functional and benchmark baseline. SMTP tests use a local TLS server; a real Proton token and inbox delivery require owner configuration. Physical HDMI, USB touch input, fresh SD boot, Pi 3B/5 and electrical communication with purchased converters remain separate hardware acceptance tests. Packages do not have the publisher's Authenticode signature.
